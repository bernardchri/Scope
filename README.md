# Scope

## Postulat

- La rédaction d'un document dans un language humain et pas machine et/ou graphique est primordiale pour que tous les partis d'un projet puissent se comprendre et avancer ensemble.
- Les incompréhensions dans les fonctionnalités sont sources de frustrations, décéptions parfois, et de pertes d'argent dans le pire des cas. Une fonctionnalité mal appréhendée peut rendre bancale un projet et inutilsable.

## Objectif

- Creation d'une mini application pour réaliser un cahier des specs.
- Commenter des maquettes, expliquer les fonctionnalités de chaque composants afin de clarifier au maximum le projet
- Genérer un pdf, lisible par un client.
- Permettre des reviews des fonctionnalités, voir d'une Estimation (Approbation d'un Directeur technique par exemple)

## Pages

Une table des matières, une page composant, une page gabarit, une page d'écriture, une page de configuration d'un projet

### Table des matières

- Infos principales du projet ( titre, personnnes intervenantes, deadlines, etc)
- Liste de différentes pages avec informations générales sur le projet
- Liste des différents composants
- Liste des différents gabarits

### Les composants

- Permet de voir comment évolue un composant suivant la largeur d'un écran (Desktop / tablette / mobile), et son contexte par rapport à d'autres éléments
- Possibilté de charger une de maquette.
- Information générales du composant, but, interet principal, si on le retrouve sur des pages
- Ajout de zone d'interets ayant leurs propres informations
